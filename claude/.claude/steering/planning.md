description: Planning and design conventions. Use when breaking down requirements, designing architecture, or creating implementation plans.
---

## Approach
- Clarify ambiguous requirements before designing
- Break work into small, independently deliverable chunks
- Identify dependencies and risks early
- Prefer simple designs — add complexity only when justified

## Architecture
- Favour proven patterns over novel ones
- Document decisions and the reasoning behind them
- Call out tradeoffs explicitly, don't hide them
- Design for the current requirements, not hypothetical future ones

## Implementation Plans
- Each task should have a clear definition of done
- Order tasks to deliver value early and reduce risk first
- Flag tasks that block others
- Keep plans in sync with reality — update when scope changes

## Output Format
- Use AsciiDoc for design/planning documents
- Summarise the plan at the top before the detail
- Use tables for comparisons, lists for steps, prose for reasoning
